YOUR FIRST GITHUB PAGES SITE

不用改代码，
把校园查询放到网上。

本项目是纯静态网站。网页文件已经准备好，不需要安装开发环境，也不需要购买域名或自己的服务器。免费 GitHub 账号使用公开仓库即可开通 GitHub Pages。

现在可以先不填资料。第一次发布空资料库也可以，之后随时补充。

1. 登录 GitHub，新建一个项目

  1. 打开 GitHub 并登录自己的账号。没有账号时，请按页面提示自行注册。
  2. 点击右上角 ＋ → New repository。
  3. 项目名填写 campus，可见性选择 Public，勾选添加 README，然后点击 Create repository。

可以使用已有账号，不要改动此前的 talks 项目。若已有同名 campus 项目，就取另一个名字，后面的链接也相应改变。

2. 上传网页文件

  1. 先把“校园查询网页包.zip”完整解压。
  2. 在刚建好的 GitHub 项目里点击 Add file → Upload files。
  3. 将解压后文件夹里面的网页文件一起拖进去，包括 index.html、data.js、styles.css、knowledge-core.js、editor-model.js、app.js、manage.html、manage.js 和本指南。.nojekyll 若能看到也一并上传。
  4. 填写简短说明，如“创建校园查询网页”，然后提交保存。新项目可以直接提交到 main；若 GitHub 要求走分支与合并流程，则完成合并后继续。

上传的是解压后的网页文件，不是 ZIP 压缩包，也不是外面那层文件夹。打开仓库首页时，应当直接看得到 index.html。

3. 打开 GitHub Pages

  1. 进入项目的 Settings → Pages。
  2. 在 Build and deployment 中，Source 选择 Deploy from a branch。
  3. Branch 选择 main，文件夹选择 /(root)，点击 Save。
  4. 等待发布，看到 Visit site 后点击打开。首次发布及后续更新可能需要几分钟，官方说明最长可能约10分钟。

最终网址形如 https://你的用户名.github.io/campus/。如果你的账号确实叫 wsl-66688，且项目名是 campus，对应网址将是 https://wsl-66688.github.io/campus/。这只是命名示例，不代表该网址已经创建。

4. 以后怎样更新资料

  1. 打开网页底部的 资料编辑。
  2. 新增资料，填写正文、地点、来源和日期，点击 加入发布文件。不想公开的先保存为草稿。
  3. 点击 下载发布文件 data.js。下载文件名必须是 data.js；若浏览器加了“(1)”，先改回原名。
  4. 回 GitHub 项目，点击 Add file → Upload files，上传新的 data.js，替换旧文件并提交。其余网页文件不需要重复上传。
  5. 等待发布完成，刷新查询页面，用刚录入的标题查一次，确认内容和页面底部更新时间。
保存表单只是保存到当前浏览器。上传替换 GitHub 的 data.js 才会更新同学看到的内容；删除本机记录也需要重新上传才能从线上移除。

同一台电脑和浏览器会记住你的编辑资料。换设备前，先“导出本机备份”。另一台设备首次打开编辑页会从当时网页的公开资料开始；已有本机资料的设备不会自动合并他人的更新。导入 JSON 或 data.js 会追加为草稿，请避免重复导入。未保存的表单内容不在备份里。

5. 发给同学前，做一次实际验证

  1. 电脑浏览器打开网址，确认查询页能显示。
  2. 手机浏览器和微信分别打开同一个网址，查询一条已发布资料。
  3. 检查来源、地点和有效期；未收录的问题应显示“资料库还没收录”。
  4. 若出现404，先确认 Pages 已发布、分支与根目录选对、文件名为小写 index.html。若旧资料没更新，先等发布完成，再刷新页面。

GitHub Pages 的访问速度和可用性会受具体网络影响，不能用电脑一次打开来代替手机、微信实测。当前项目未替你注册账号或创建线上网址。

这个版本的范围

资料保存在公开的 data.js 文件里，浏览器在本地完成查询。草稿留在编辑者当前浏览器，不会导出到公开文件；本机备份包含草稿，应保存到自己的电脑。发布文件中的全部资料均为公开内容，包括设置了未来生效日期的资料，日期只是查询筛选条件。

没有大模型、付费调用或自建服务器。首版最多500条资料，每条正文最多20000字。网页编辑页没有 GitHub 写入权限；普通同学即使打开它，也只能修改自己浏览器里的资料。要让全站更新，仍需能登录并修改对应的 GitHub 仓库。
